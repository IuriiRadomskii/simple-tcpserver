# Роадмап: TCP-сервер на Go (для тех, кто знает Java)

Цель: сервер, который принимает запрос байтами и отвечает. Код вы пишете сами,
здесь только описание шагов, команды и аналогии с Java.

---

## Этап 0. Минимум языка (1–2 вечера)

Пройдите **A Tour of Go**: https://go.dev/tour (есть русская версия). Разделы
Basics, Methods and interfaces и Concurrency нужны обязательно, остальное можно пролистать.

### Шпаргалка «Java → Go»

| Java | Go | Комментарий |
|---|---|---|
| `class` с полями и методами | `struct` + методы, объявленные отдельно | Наследования нет, вместо него композиция (встраивание структур) |
| `interface` + `implements` | `interface` без `implements` | Тип реализует интерфейс автоматически, если у него есть нужные методы («утиная типизация» на этапе компиляции) |
| `public` / package-private | Имя с **заглавной** буквы видно снаружи пакета, со строчной нет | `Listen` публичный, `listen` приватный для пакета |
| `package com.foo.bar;` | `package bar` | Пакет = **папка**. Все файлы в одной папке принадлежат одному пакету |
| `public static void main` | `func main()` в `package main` | Одна такая функция на программу |
| Исключения, `throws`, `try/catch` | Функция возвращает `(результат, err)`, вы проверяете `err != nil` | Ошибка — обычное значение. Исключений нет (`panic` только для катастроф) |
| `finally` / try-with-resources | `defer conn.Close()` | Выполнится при выходе из функции |
| `byte[]` | `[]byte` (слайс) | Слайс — «окно» в массив, похож на `ByteBuffer` без позиции |
| `null` | `nil` | |
| Виртуальные потоки (Java 21) | **Горутины**: `go f()` | Очень лёгкие, можно запускать тысячи. Аналог `Thread.ofVirtual().start(...)` |
| `BlockingQueue` | Каналы (`chan`) | Для этого проекта почти не нужны |
| `Thread.interrupt()`, токены отмены | `context.Context` | Для корректной остановки сервера |
| Javadoc | `go doc <пакет>.<имя>` | Документация прямо в терминале |

## Этап 3. Структура проекта

```
tcp-server/
├── go.mod
├── cmd/
│   ├── server/main.go      ← точка входа сервера (как класс с main)
│   └── client/main.go      ← точка входа тестового клиента
└── internal/
    ├── protocol/
    │   ├── protocol.go     ← как читать/писать сообщение из байтов
    │   └── protocol_test.go
    └── server/
        ├── server.go       ← слушать порт, принимать соединения
        └── server_test.go
```

Сравнение с Maven:
- **Нет `src/main/java` и `src/test/java`.** Тесты лежат рядом с кодом в файлах `*_test.go`.
- **`cmd/`** — несколько исполняемых программ в одном модуле. Похоже на несколько main-классов, только каждый собирается в свой `.exe`.
- **`internal/`** — пакеты, которые нельзя импортировать из других модулей. Это проверяет компилятор, аналог неэкспортируемых пакетов в `module-info.java`.
- Пакет импортируется по пути: `tcp-server/internal/protocol`.

Можно начать с одного `main.go` в корне и разложить код по папкам на этапе 6.

## Этап 4. Понять протокол (до написания кода!)

TCP передаёт **поток байтов, а не сообщения**. В Java то же самое: `InputStream.read(buf)`
может вернуть меньше байтов, чем отправили, или склеить два сообщения.

Выберите способ разделять сообщения:

1. **Разделитель** (`\n`). Просто, подходит для текста.
   Java: `BufferedReader.readLine()` → Go: `bufio.Reader` + `ReadBytes('\n')`
2. **Префикс длины**: 4 байта длины (big-endian) + тело. Подходит для любых байтов. **Рекомендую этот вариант.**
   Java: `DataInputStream.readInt()` + `readFully(buf)` → Go: `encoding/binary` + `io.ReadFull`

Решите, что сервер делает с запросом. Для начала хватит **эха** (вернуть то же самое).

## Этап 5. Сервер-эхо (первая рабочая версия)

### Карта «Java-сокеты → Go»

| Java | Go |
|---|---|
| `new ServerSocket(8080)` | `net.Listen("tcp", ":8080")` |
| `serverSocket.accept()` | `listener.Accept()` → возвращает `net.Conn` |
| `Socket` | `net.Conn` |
| `socket.getInputStream()` / `getOutputStream()` | Не нужно: `net.Conn` сам умеет `Read` и `Write` |
| `InputStream` / `OutputStream` | интерфейсы `io.Reader` / `io.Writer` |
| `read()` вернул `-1` | ошибка `io.EOF` (клиент закрыл соединение) |
| `BufferedInputStream` / `BufferedOutputStream` | `bufio.Reader` / `bufio.Writer` (не забывать `Flush`) |
| `socket.setSoTimeout(ms)` | `conn.SetReadDeadline(время)` (абсолютное время, а не длительность) |
| `new Thread(() -> handle(s)).start()` | `go handle(conn)` |
| `new Socket("localhost", 8080)` | `net.Dial("tcp", "localhost:8080")` |

### Алгоритм
- [ ] Открыть слушающий сокет на порту
- [ ] Бесконечный цикл `Accept`
- [ ] Каждое соединение передать в отдельную горутину
- [ ] В обработчике первым делом `defer conn.Close()`
- [ ] Цикл: прочитать запрос → сформировать ответ → записать
- [ ] На `io.EOF` спокойно выйти, другие ошибки залогировать

### Запуск
```powershell
go run ./cmd/server        # как mvn exec:java, компилирует и сразу запускает
```

### Проверка без своего клиента
- `ncat localhost 8080` (идёт в комплекте с Nmap). Подходит для протокола с `\n`.
- `Test-NetConnection localhost -Port 8080` проверит только, что порт открыт.

## Этап 8. Тесты

| Go | Java |
|---|---|
| файл `xxx_test.go`, функции `TestXxx(t *testing.T)` | класс JUnit с `@Test` |
| `t.Errorf(...)` / `t.Fatalf(...)` | `assertEquals` (продолжить тест / прервать тест) |
| `go test ./...` | `mvn test` |
| `go test -race ./...` | Встроенный детектор гонок между горутинами. В Java прямого аналога нет |
| `go test -cover ./...` | JaCoCo |

Что протестировать:
- [ ] `protocol`: записать сообщение в `bytes.Buffer` (аналог `ByteArrayOutputStream`), прочитать обратно, сравнить
- [ ] `protocol`: пустое сообщение, большое сообщение, обрезанные данные (должна быть ошибка)
- [ ] `server`: поднять сервер на `":0"` (свободный порт выберет ОС, как `new ServerSocket(0)`), подключиться, проверить ответ
- [ ] Для тестов без сети пригодится `net.Pipe()`: пара связанных `net.Conn` в памяти

## Этап 9. Довести до ума

- [ ] Таймауты чтения и записи (`SetReadDeadline` / `SetWriteDeadline`)
- [ ] Ограничение максимальной длины сообщения (иначе клиент пришлёт «длина = 4 ГБ» и сервер попытается выделить столько памяти)
- [ ] Корректная остановка по Ctrl+C: `os/signal` + `context` (аналог shutdown hook в Java)
- [ ] Дождаться завершения активных соединений при остановке: `sync.WaitGroup` (аналог `CountDownLatch` / `ExecutorService.awaitTermination`)

## Команды на каждый день

```powershell
go run ./cmd/server                        # запустить
go build -o bin/server.exe ./cmd/server    # собрать .exe (как mvn package, но на выходе нативный бинарник)
gofmt -w .                                 # форматирование (единый стиль, спорить не о чем)
go vet ./...                               # статический анализ (лёгкий аналог SpotBugs)
go test ./...                              # тесты
go test -race ./...                        # тесты + поиск гонок
go mod tidy                                # порядок в зависимостях
go doc <пакет>.<имя>                       # документация
```

`./...` означает «все пакеты в этой папке и во вложенных».
